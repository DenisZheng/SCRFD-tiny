## 5. 口径边界（重要）

### 5.1 不能与 README 表格对比

README 中的 `SCRFD-tiny(ours) 89.23 / 87.60 / 67.15` 与本表存在**两层差异**：

| 维度 | README 表格 | 本文件 |
| --- | --- | --- |
| 输入尺寸 | **640** | **320** |
| 训练轮数 | 1200 epoch 从头训练 | 200 epoch 微调 |

320 输入下 17.3% 的人脸宽度小于 8 px，缩放后小于最小 anchor（8 px），物理上无法检出；
640 输入则不存在这个问题。因此 Hard 子集的差距主要来自分辨率，而非模型质量差异。

### 5.2 与 `main.py --test` 的 mAP 不是同一指标

| 指标 | 定义 |
| --- | --- |
| `step.csv` 的 `mAP` = 0.167 | IoU **0.5:0.95 平均**（COCO 风格），难得多 |
| 本文件的 `AP` = 86.36 / 78.90 / 41.77 | IoU **0.5 单点**，分 Easy/Medium/Hard |

两者相差数倍属正常，不能互相替代或引用时混用。

### 5.3 关键点精度未评估

WIDER Face 的 val 标注 (`label.txt`) **只有检测框、没有 5 点关键点**。因此：

- 本评估**只评检测框**，不评关键点
- `step.csv` 里 `kpt` loss 从 0.093 降到 0.069 只能说明关键点分支在收敛，
  **不能作为关键点精度的证据**
- 关键点精度需另行准备带 5 点的验证集，或做人工抽检

### 5.4 数据集标注规范说明

官方 `retinaface_gt_v1.1` 中 train 集只有 **47.7%** 的人脸有完整 5 点，
**52.3% 完全没有**。这不是数据损坏，而是 RetinaFace 的标注规范：
只对"可标注"（尺寸足够大）的人脸标注关键点。

实测交叉验证：无关键点的脸中位宽仅 10 px（面积 120 px²），有关键点的为 28 px（992 px²），
且无关键点比例随尺寸严格单调上升（0–8 px 为 96.9% → 128 px+ 仅 1.9%）。

详见 [Docker 训练手册第 19.3.4 节](../../SCRFD-tiny-Docker训练流程.md)。

## 7. 复现步骤

```bash
# 1) 构建镜像（含 scipy，评估器需要）
docker build --file Dockerfile.scrfd-tiny --tag scrfd-tiny:torch2.5.1-cu124 .

# 2) 准备数据（官方 retinaface_gt_v1.1 标注 + WIDER 图片）
python3 tools/build_from_gt.py \
  --gt-root /path/to/retinaface_gt_v1.1 \
  --images-root /path/to/wider \
  --out /datasets/WIDERFace --splits train val --mode hardlink

# 3) 训练（--save-dir 指向新目录，勿用默认 ./weights）
python3 -u main.py --train --data-dir /datasets/WIDERFace \
  --save-dir /runs/ft320-YYYYMMDD --weights weights/best.pt \
  --input-size 320 --batch-size 32 --epochs 200

# 4) 评估
python3 tools/export_wider_preds.py --ckpt /runs/ft320-YYYYMMDD/best.pt \
  --images-root /datasets/WIDERFace/images/val --out /runs/ft320-YYYYMMDD/wouts \
  --input-size 320
python3 tools/widerface_evaluation/evaluation.py \
  -p /runs/ft320-YYYYMMDD/wouts -g tools/widerface_evaluation/ground_truth
```
